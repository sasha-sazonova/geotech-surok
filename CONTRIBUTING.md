# Как участвовать

## Правила, которые не обсуждаются

1. **Число без источника не принимается.** Любая новая формула или коэффициент должны иметь
   запись в `traceability.yml`: документ → редакция → пункт → формула → код → тест.
2. **Нормативные значения берутся только из официального текста нормы** и сверяются с датой
   и URL (`docs/norm-sources/`). Справочники (в том числе Engineering ToolBox) — класс
   `reference`, они не заменяют норму.
3. **«Не определено» — законный результат.** Если данных или подтверждённой ячейки нормы нет,
   функция обязана отказать, а не вернуть правдоподобное число.
4. **Ошибки исправляются в коде и процедурах, а не в артефактах.** Отчёт не подгоняется под
   желаемый вывод; при исправлении создаётся новая ревизия с новым id задания, старая сохраняется.

## Порядок работы

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.lock
make verify          # должно быть зелёным до и после ваших изменений
```

1. Изменили расчёт — обновите тесты и, если результат изменился осознанно, `make regen`.
2. Добавили пункт нормы — добавьте запись в `traceability.yml`; валидатор не пропустит сироту.
3. Прогоните `make verify` и приложите вывод к пул-реквесту.

## Чего не делать

- Не добавлять зависимости без нужды: ядро должно ставиться из `requirements.lock`.
- Не отключать проверки трассируемости, чтобы «прошло».
- Не коммитить результаты расчётов как golden-файлы, если они не проверены вручную или оракулом.
