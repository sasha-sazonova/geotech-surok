Geotechnics · normative layer · human in the loop

Surok

A geotechnical agent that prepares calculations so every number can be traced back to a clause.

Not a solver, not a one-formula calculator. An engineering co-pilot: data → clause → formula → implementation → test → report.

Spec v1.6 · 22 Oct 2026 · OpenClaw

01 · Problem

The number exists, the justification does not

  • Calculations live in proprietary silos: a project file, but no chain to the clause.
  • Reports are retyped by hand, so numbers lose their source data and software version.
  • Expert review asks for provenance and gets a screenshot.
  • AI output without traceability cannot be checked, so it is worth nothing.

02 · Purpose

Turn a calculation into a verifiable artifact

Three jobs the agent exists for.

  • Keeps the normative registry. Document → edition → amendment → clause → formula → implementation → test. Only confirmed editions enter a calculation.
  • Prepares and checks the calculation. Open-source solvers in frozen environments, cross-tool verification, soil parameter passport with provenance.
  • Assembles the justification package. Report with substituted numbers, traceability table, honest status for every check.

03 · Boundaries

What it does and does not do

Does

  • prepares calculations, reports and draft notes;
  • maintains the normative registry and audit logs;
  • audits input data and drafts clarification requests;
  • proposes a calculation route and an independent check;
  • returns “not determined” instead of a silent skip.

Does not

  • sign or release documentation;
  • replace the responsible engineer or independent review;
  • recalculate released reports silently;
  • use unverified editions of norms;
  • publish anything outward without human acceptance.

04 · How to use

Four steps

Step 1Brief: object, design stage, what to calculate and to which code.
Step 2Data: investigation report, GEF/CPT, AGS4, boreholes, SPT, groundwater, loads, geometry.
Step 3Calculation: route from the registry, frozen environment, cross-tool verification.
Step 4Report: formulas with substituted numbers, check statuses, limits, traceability table.

Then a human takes over: the specialist verifies numbers and clauses, signs and releases. The agent prepares; it does not sign.

08 · Inside

Workflows: four pipelines

P-1Investigation → statistics: GEF/CPT, AGS4, GOST 20522 → parameter passports
P-2Slopes: xslope + pyslope, factor-of-safety cross-check
P-3Piles: OpenPile + De Beer, reference comparison is mandatory
P-4Report: pint → Jinja2 → PDF/DOCX, traceability table

Every pipeline has a fixed point where human cross-check is mandatory. A discrepancy beyond tolerance stops the run instead of being averaged away.

09 · Reproducibility

A result without a freeze is not reproducible

  • Calculation runs on a compute node, not on the agent machine: job directory with input, status and output.
  • Environment is fixed by a freeze: platform, host, package versions.
  • Inputs and outputs travel with SHA-256 checksums; the job journal goes into the report.
  • Three retries, then an honest “no result”. Local substitution and rough estimates are forbidden.

10 · Discipline

Four statuses that must not be mixed

StatusMeaning
Method implementedcode exists and runs
Scenario reproduced and cross-checkednumbers match an independent solution
Normative route verifiedclause → formula → implementation → test is complete
Not determineddata or a confirmed edition is missing

“Method implemented” is not “normative route verified”. A missing check is never a green tick.

12 · Audience

Geotechnical teams, not everyone

Who it is for

  • design institutes and bureaus with a geotechnical department;
  • foundation and soil engineers;
  • experts reviewing third-party calculations;
  • teams that need a report package for expert review.

Who it is not for

  • anyone looking for a one-formula calculator;
  • replacing an FEM package by module breadth;
  • releasing documentation without a specialist.

The open niche: normative protocol and review of third-party calculations as a service. Solver vendors do not cover it.
