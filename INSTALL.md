# Установка и первый расчёт

Инструкция проверена на чистой машине: macOS, Python 3.9.6, установка с нуля заняла **27 секунд**,
после неё `make verify` даёт **78 passed**.

Ничего, кроме Python и git, ставить не нужно. Docker — по желанию.

---

## 0. Самый быстрый путь: один скрипт

```bash
git clone https://github.com/sasha-sazonova/geotech-surok.git
cd geotech-surok
./install.sh                  # ядро (СП 22 + СП 24)
# или
./install.sh --with-engines   # плюс 7 методов устойчивости откосов и подпорные стены
```

Скрипт сам: проверит Python и свободное место, создаст `.venv`, поставит зависимости
из `requirements.lock` (версии зафиксированы), при `--with-engines` доставит движки
и прогонит `make verify`. Ничего в систему не устанавливает — всё внутри папки проекта.

Если `./install.sh` не подходит — ниже пошаговая установка вручную.

## 1. Что нужно

| Требование | Минимум | Проверено на |
|---|---|---|
| Python | **3.9** | 3.9.6, 3.12, 3.13 (проверено вручную), 3.12 (CI, Docker) |
| git | любая версия | 2.x |
| ОС | macOS, Linux, Windows (WSL или Git Bash) | macOS 14, Ubuntu 24.04 |
| Docker | не обязателен | используется только для проверки «на чистой машине» |

Проверить версию Python:

```bash
python3 --version
```

Если версия ниже 3.9 — обновите Python или используйте Docker (раздел 5).

**Debian/Ubuntu:** пакет `python3-venv` часто не установлен, и `python3 -m venv` падает с
`ensurepip is not available`. Поставьте его заранее:

```bash
sudo apt install python3-venv
```

## 2. Установка (macOS / Linux)

```bash
git clone https://github.com/sasha-sazonova/geotech-surok.git
cd geotech-surok
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
```

Четыре команды, дальше — проверка.

---

## 3. Проверка, что всё работает

```bash
make verify
```

Ожидаемый вывод:

```
TRACEABILITY: OK (15 clauses, 47 tests)
78 passed
```

Если `make` не установлен (частый случай на Windows и в минимальных образах), те же две проверки
запускаются напрямую:

```bash
python tools/validate_traceability.py
python -m pytest -q
```

## 4. Первый расчёт

```bash
python examples/quickstart_d1.py
```

Скрипт считает фундамент мелкого заложения по СП 22.13330.2016. Ожидаемый вывод:

```
R  (расчётное сопротивление) : 215.62 кПа
p  (среднее давление)        : 286.0 кПа
s  (осадка)                  : 4.232 см
Hc (сжимаемая толща)         : 3.6 м

Проверки:
  p_le_R     СП 22.13330.2016, п.5.6.7, ф.(5.7)
             286.00 против 215.62 → не выполняется
  s_le_su    СП 22.13330.2016, п.5.6.31, ф.(5.16); п.5.6.41; прил. Г, табл. Г.1
             4.23 против 10.00 → выполняется
```

Свой расчёт — два равноправных способа.

**Способ 1 (без программирования): сценарий YAML.**

```bash
python tools/run_scenario.py scenarios/d1-foundation.yaml
```

Сценарий описывает геометрию, нагрузку и грунт:

```yaml
geometry: {b: 2.0, l: 2.4, d: 1.8}
loads:    {N: 1200.0}
soil:
  IGEE1: {gamma_kNm3: 18.5, phi_deg: 16, c_kPa: 18, E_MPa: 9, thickness_below_base_m: 4.0}
  above_base_gamma_kNm3: 17.5
  UGV_m: 3.2          # глубина УГВ вниз от поверхности
  data_bottom_m: 5.8  # до какой глубины есть данные
```

Скопируйте `scenarios/d1-foundation.yaml`, поправьте числа, запустите. Флаг `--json` даёт
машиночитаемый результат. Если в сценарии остались устаревшие коэффициенты, раннер не подменит
их молча: он посчитает по проверенным значениям нормы и **напечатает предупреждение**.

**Способ 2 (Python API):** блок «ВАШИ ДАННЫЕ» в `examples/quickstart_d1.py`.

Коэффициенты табл. 5.4/5.5/5.8, осреднение γ по b/2, kz для b ≥ 10 м и границу сжимаемой толщи
библиотека берёт из нормы сама.

**Сколько нужно данных.** Для осадки слои должны быть описаны примерно до глубины `d + 2·b`
(ниже этого уровня напряжение от фундамента падает до 50 % бытового и толща заканчивается).
Если данные кончаются раньше, расчёт осадки вернёт «не определено» — это требование п.5.6.41,
а не ошибка программы.

**«Не определено» — это нормальный результат.** Так система отвечает, когда данных не хватает или
ячейка нормы не подтверждена. Это не сбой и не повод «подкрутить» число: см. `docs/status.md`.

## 5. Вариант без установки: Docker

```bash
docker build -t geotech-surok .
docker run --rm geotech-surok
```

Внутри контейнера выполняется тот же `make verify`. Ничего в систему не устанавливается.

---

## 6. Windows

Работает через **WSL** (рекомендуется) или **Git Bash**. Команды те же, что в разделе 2;
активация окружения в Git Bash:

```bash
source .venv/Scripts/activate
```

`make` в Windows обычно нет — используйте прямые команды из раздела 3.

## 7. Если что-то пошло не так

| Симптом | Причина | Решение |
|---|---|---|
| `ModuleNotFoundError: No module named 'yaml'` | не активировано окружение или не поставлены зависимости | `source .venv/bin/activate && pip install -r requirements.lock` |
| `No module named 'calc'` | запуск не из корня репозитория | `cd geotech-surok` и повторить |
| `make: command not found` | нет make | запускать `python -m pytest -q` и `python tools/validate_traceability.py` напрямую |
| `command not found: python` | в системе только `python3` | использовать `python3` вместо `python` |
| Тесты падают на `test_units.py` | сломанная установка Pint | `pip install --force-reinstall Pint==0.24.4` |
| Долгая установка на Apple Silicon | сборка колёс под arm64 | первый раз до 2 минут, дальше из кеша |
| `ensurepip is not available` | в Debian/Ubuntu нет пакета `python3-venv` | `sudo apt install python3-venv` |
| `не определено (граница сжимаемой толщи вне данных)` | данных о грунте не хватает до глубины, где σzp ≤ 0.5·σzg | нужны слои примерно до `d + 2·b` ниже поверхности; это не сбой, а требование нормы |

## 9. Что делать дальше

1. Поменять данные в `examples/quickstart_d1.py` на свои и посмотреть, какие проверки проходят.
2. Прочитать `docs/status.md` — там честный список того, что система считает, а что нет.
3. Если нужен расчёт, которого нет в списке реализованных, — это не «докрутить формулу», а
   поставить задачу: см. `workspace-geotech_surok/procedures/` (политика статусов).
