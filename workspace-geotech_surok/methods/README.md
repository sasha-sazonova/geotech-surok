# Методики: модули, верификация, приёмка

Методика в этом проекте — не «формула в промпте», а модуль с паспортом: что реализовано,
на какой пункт нормы опирается, чем проверено, какие ограничения несёт результат.

## Четыре уровня, которые нельзя смешивать

1. **Метод реализован** — код существует и запускается.
2. **Сценарий воспроизведён и сверен** — числа совпали с независимым решением.
3. **Нормативный маршрут проверен** — цепочка «пункт → формула → реализация → тест» полна.
4. **Не определено** — полноценный статус: данных или подтверждённой нормы не хватает.

«Метод реализован» ≠ «нормативный маршрут проверен». Отсутствующая проверка никогда не
превращается в зелёную галочку.

## Что проверяется и чем

| Вопрос | Инструмент проверки |
|---|---|
| Формула реализована верно | эталонный расчёт с ручной подстановкой |
| Реализация совпадает с независимым решением | второй инструмент из реестра (например, xslope ↔ pyslope) |
| Нормативный маршрут полон | карточка сценария: пункт, редакция, формула, тест |
| Результат воспроизводим | freeze окружения, хост, SHA-256, журнал задания |
| Применимость модели | паспорт допуска модуля с явными ограничениями |

## Паспорт допуска модуля

Для каждого модуля фиксируется: версия, зависимость от редакции нормы, эталонные примеры,
диапазон применимости, известные ограничения и дата последней верификации.
Модуль без паспорта в выдачу не идёт.

## Смена редакции нормы

Выход изменения к СП/ГОСТ запускает:

1. запись в реестр со статусом `draft`;
2. поиск затронутых сценариев по графу зависимостей;
3. ре-валидацию эталонов на новой редакции;
4. обновление паспорта модуля с датой.

До завершения цикла расчёты, опирающиеся на изменённый пункт, возвращают «требует проверки».

## Единица учёта

Учёт ведётся не по «сообщениям в чате», а по воспроизведённым сценариям: карточка сценария,
входные данные, freeze, протокол, отметка приёмки. Сценарий без воспроизведения не считается
выполненным.
