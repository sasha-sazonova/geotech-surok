# Протокол заданий на вычислительный узел

Тяжёлые расчёты не выполняются на машине агента. Задание уходит на вычислительный узел
асинхронно, результат забирается с контрольными суммами.

## Почему так

- Канал до узла нестабилен: интерактивный SSH рвётся на длинных расчётах.
- Расчёт должен переживать разрыв сессии и перезапуск.
- Результат без зафиксированного окружения невоспроизводим, поэтому freezе едет вместе с заданием.

## Схема

```
jobs/<id>/
├── in/        входные данные, карточка сценария, freeze окружения
├── status     queued | running | done | failed
└── out/       результаты, протокол, SHA-256
```

1. Агент создаёт каталог задания и копирует входные данные.
2. Очередь разбирает runner по расписанию: берёт задание, поднимает окружение из freeze,
   выполняет расчёт, пишет статус.
3. Агент опрашивает статус и забирает результаты с контрольными суммами.
4. `out/` попадает в протокол только после сверки SHA-256.

## Анти-фоллбэк

Три повтора. Если расчёт не завершился — фиксируется честный статус **«расчёта нет»**.
Локальная подмена результата, «примерная оценка» или расчёт на другой модели вместо упавшей
запрещены. Отсутствие результата — это результат.

## Что фиксируется в журнале

| Поле | Зачем |
|---|---|
| id задания и сценарий | воспроизводимость |
| freeze окружения и хост | результат без freeze не воспроизводим |
| время старта, завершения, повторы | диагностика |
| SHA-256 входов и выходов | контроль целостности |
| версия runner | совместимость |

## Запреты

- интерактивные расчёты по SSH;
- изменение кода или окружения во время выполнения задания;
- выдача результата без контрольных сумм и статуса.
